# Finsky — мобильный protobuf-API Google Play

Веб-выдача Play с 2022 отдаёт одну страницу (~19–30 приложений) и пагинации не
имеет вовсе, поэтому `scrapers/googleplay.ts` физически не может дать позицию
глубже топ-30 (см. комментарий в шапке того файла). Мобильный клиент Play ходит
в другой API — `android.clients.google.com/fdfe/*`, protobuf поверх HTTP — и там
у кластера выдачи есть `containerMetadata.nextPageUrl`, то есть выдача листается.

Этот модуль — порт минимально необходимой части клиента: регистрация устройства,
авторизация, поиск с обходом страниц.

## Происхождение и лицензия

Схема `proto/GooglePlay.proto`, профили `devices/*.properties`, заголовки в
`targets.ts` и логика auth/search взяты из
[AuroraOSS/gplayapi](https://gitlab.com/AuroraOSS/gplayapi) — GPL-3.0-or-later.
Это единственная поддерживаемая в живом состоянии реализация (апстрим
обновлялся в июле 2026); `MCMrARM/Google-Play-API` заброшен с 2020 года.

GPL-3.0 не содержит сетевой оговорки AGPL, поэтому использование внутри
серверного сервиса не обязывает раскрывать сервис. При переносе кода в
клиентское приложение или расширение условия меняются — проверить отдельно.

## Как получить aas_token

Логин делает человек, скриптом это не автоматизируется (2FA).

1. Открыть <https://accounts.google.com/EmbeddedSetup> и войти в аккаунт,
   который не жалко (устройства и история привязываются к нему).
2. Дойти до экрана согласия и нажать «Я принимаю».
3. В DevTools → Application → Cookies для домена `google.com` найти cookie
   `oauth_token`, значение начинается с `oauth2_4/`. Скопировать.
4. Сразу обменять — токен одноразовый и живёт минуты:

   ```
   npx tsx src/scrapers/finsky/aas.ts you@gmail.com "oauth2_4/..."
   ```

5. Полученные `FINSKY_EMAIL` / `FINSKY_AAS_TOKEN` положить в окружение.
   `aas_token` — полноценный доступ к аккаунту Google, обращаться как с паролем.

## Пробник глубины

```
FINSKY_EMAIL=... FINSKY_AAS_TOKEN=... \
  npx tsx src/scrapers/finsky/probe.ts "roblox" ru_RU com.roblox.client 15
```

Печатает, сколько позиций реально отдал API, топ-10 и хвост за 30-й позицией —
то есть ровно то, чего веб-парсер дать не может.

## Переменные окружения

| переменная | по умолчанию | смысл |
|---|---|---|
| `FINSKY_EMAIL` | — | аккаунт Google |
| `FINSKY_AAS_TOKEN` | — | долгоживущий токен аккаунта |
| `FINSKY_DEVICE` | `px_9a` | профиль из `devices/` |
| `FINSKY_LOCALE` | `en_US` | локаль запроса (`ru_RU`, `uk_UA`, …) |
| `FINSKY_STATE_PATH` | `./.finsky-state.json` | кэш gsfId и токенов |

## Что важно знать при эксплуатации

- **Состояние обязательно кэшировать.** Каждый `/checkin` регистрирует НОВОЕ
  устройство на аккаунте; их число не бесконечно. `.finsky-state.json` в
  `.gitignore`, на Railway контейнер эфемерный — состояние нужно перенести в БД
  до продакшена.
- **Гео определяется аккаунтом и IP.** Смена `FINSKY_LOCALE` меняет язык, но не
  страну витрины. Для честных позиций по стране нужен резидентский прокси этой
  страны (общий пул из `scrapers/proxy.ts` подхватывается автоматически) и, по
  хорошему, аккаунт, зарегистрированный в ней.
- **ToS сознательно не принимаем** — `acceptTos` привязывает устройство к
  аккаунту. В апстриме этот вызов тоже закомментирован.
- **Это нарушение ToS Google Play.** Аккаунты банят — это ожидаемая часть
  эксплуатации, закладывать ротацию.
- **Протокол недокументированный.** `X-DFE-Encoded-Targets` и `X-DFE-Phenotype`
  версионные: при поломке обновлять `targets.ts` из апстрима целиком, а не
  править руками.

## Статус: для рангов НЕ используется

Цепочка целиком проверена вживую на реальном аккаунте: `checkin` → мастер-токен
(`aas_et/…`) → токен сервиса googleplay → `uploadDeviceConfig` → `acceptTos` →
`/fdfe/search` отвечает 200, пагинация по `nextPageUrl` ходит.

Но **нативный поиск для ASO непригоден**:

- на брендовый запрос («roblox») приходит точное совпадение + кластер «Вам
  также могут понравиться», и его пагинация даёт 136 приложений, порядок
  которых не совпадает с реальной выдачей Play (TikTok и Instagram в топе по
  запросу «roblox»);
- на обычный запрос («photo editor», «фоторедактор») приходит ПУСТОЙ список:
  1.3-1.7 КБ, ноль карточек, а континуация `searchList` отвечает 424-496 байт
  без единой карточки. Принятие ToS это не меняет.

Полную ранжированную выдачу (230-250 позиций, порядок совпадает с
`scrapers/googleplay.ts`) отдаёт batchexecute-RPC витрины — **см.
`scrapers/gplayRpc.ts`**. Он не требует ни аккаунта, ни устройства, ни ToS.
Сама Aurora Store пришла к тому же: её `helpers/web/WebSearchHelper.kt`
ищет через RPC, а не через Finsky.

Модуль оставлен: он рабочий и даёт то, чего у RPC нет — карточки приложений с
точным `downloadCount`, `bulkDetails` пачкой и данные, доступные только
авторизованному клиенту Play. Если понадобится — фундамент готов.
