# Калибровка точности метрик по эталону FoxData

Зачем: перед продажей нужно ЗНАТЬ реальную ошибку volume/difficulty
(средняя ошибка MAE на шкале 5-100) и опубликовать её как пруф точности.
Инструментарий уже в репозитории — нужен только свежий эталон.

## Что нужно от тебя

1. Свежая выгрузка FoxData «Keywords Ranked» (XLSX) по 2-3 приложениям
   (желательно разных ниш и размеров), страна US + одна локальная (ua/de).
   Колонки: `Keyword`, `Ranking`, `Vol`, `Diff`, `Results`.
2. Либо готовый JSON для compareFox (см. формат ниже).

## Шаг 1. XLSX → JSON эталона

Вариант А — напрямую JSON:

```jsonc
// fox-us-544007664.json
{
  "platform": "ios",
  "appId": "544007664",
  "country": "us",
  "language": "en",
  "rows": [
    { "term": "photo editor", "rank": 12, "volume": 49, "difficulty": 46 }
    // ... остальные ключи из выгрузки
  ]
}
```

Вариант Б — если есть только XLSX, есть импортёр в БД (`npm run import-xlsx`),
но для калибровки удобнее JSON: колонки Keyword/Ranking/Vol/Diff мапятся в
term/rank/volume/difficulty 1:1.

## Шаг 2. Сверка (live-прогон скрапера по тем же ключам)

```bash
npx tsx src/compareFox.ts ./fox-us-544007664.json --signals-out=./signals-us.json
```

Выход: таблица term-by-term + сводка:
- `RANK: совпало ±3 поз.` — целевое значение ≥ 80% (учитывая живую флуктуацию выдачи)
- `VOL: MAE` — целевое ≤ 12 после калибровки весов
- `DIFF: MAE` — целевое ≤ 15

`--signals-out` пишет сырые сигналы формул — вход для шага 3.

## Шаг 3. Подбор весов

```bash
npx tsx src/calibrateWeights.ts ./signals-us.json --write
```

`--write` кладёт подобранные веса в `weights.json` (переопределяет дефолты из
`src/analytics/weights.ts` посекционно). После записи повторить шаг 2 — MAE
должна упасть.

Несколько датасетов: объединить rows из разных приложений одной страны в один
signals-файл даёт устойчивее веса, чем калибровка по одному приложению.

## Шаг 4. Зафиксировать результат

1. `weights.json` задеплоить вместе с сервисом (или WEIGHTS_PATH на Railway volume).
2. Результат сверки (n ключей, MAE до/после, % rank hit) записать сюда и на
   лендинг/листинг — это маркетинговый пруф («volume within ±N of FoxData on a
   sample of X keywords»).

## Важные оговорки

- Прогонять сверку в момент, когда ASA-сессия жива (`/health/asa` → healthy:true),
  и отдельно с выключенной — чтобы знать точность ОБОИХ режимов (точный ASA
  и эвристический фолбэк).
- GP rank глубже топ-30 скрапер не видит (глубина веб-выдачи) — compareFox
  такие случаи корректно исключает из промахов (`глубже нашей выдачи`).
- Флуктуация выдачи Apple ±1-3 позиции — это шум самой выдачи, не ошибка.
